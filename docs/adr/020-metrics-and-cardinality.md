# ADR-020: Prometheus metrics with enforced low cardinality; Grafana dashboards as code

**Status:** Accepted

## Context

Logs with correlation IDs explain one request. Operating the system needs rates, latencies
and backlogs across all of them: is the outbox keeping up, is the cache helping, are consumers
lagging, are sockets being dropped. Metrics become useless (and expensive) when labels carry
per-entity values.

## Decision

- **`prom-client`** in every service through `@dpp/observability` (`Metrics`): default label
  `service`, Node process metrics, and helpers that **reject forbidden label names** at
  registration: any `*_id`/`*Id` label for users, projects, tasks, workspaces, requests,
  events, correlations, comments or attachments, and `url`, `path`, `key`, `email`. A guard in
  code, not a convention.
- **HTTP:** `http_requests_total` and `http_request_duration_seconds` labelled by method,
  **route template** (`/tasks/:id`, never the raw path; unmatched → `unmatched`) and status
  class.
- **Pipeline:** outbox pending count and oldest pending age (gauges read at scrape time),
  published/failed/retried/stale-claim counters and publish latency; per-consumer
  processed/failed/retries/dead-letters and processing time; activity outcomes; cache
  hits/misses/errors (`cache_operations_total{cache,result}`); realtime connections, rooms,
  auth failures, subscription refusals, broadcasts, slow-client and heartbeat disconnects,
  duplicates suppressed; DB pool connections by state and waiting requests.
- **`/metrics` is private:** served on each service's own port inside the VPC; the gateway does
  not route it and CloudFront only forwards `/api/*`.
- **Ratios and percentiles are computed in PromQL**, never averaged in code: hit rate =
  `hits / (hits + misses)` over a window; p95 = `histogram_quantile(0.95, sum by (le) (rate(…_bucket[5m])))`.
- **Dashboards as code:** four Grafana dashboards (system overview, event pipeline, cache,
  realtime) generated by `infrastructure/observability/grafana/dashboards.py` and provisioned
  in Compose. `tests/architecture/metrics.test.ts` fails if a dashboard queries a metric the code
  does not define or uses a per-entity label; `tests/integration/dashboards.int.test.ts` runs
  every dashboard expression against a real Prometheus.

## Consequences

- Locally: Prometheus + Grafana in Compose. In AWS there is **no managed Prometheus/Grafana**
  (cost); metrics are read from `/metrics` inside the VPC (ECS Exec) and correlated with
  CloudWatch's free ECS/RDS metrics. The load tests used exactly that.
- Adding a label is a deliberate act: the guard throws for the forbidden names, and review
  covers the rest.
